# 求是西行 · 1937

根据《求是西行-1937_开发精简版_图片标注.md》制作的中文历史互动叙事网页游戏。玩家从 2026 年校史馆进入浙江大学西迁往事，经历迁校、护书、求学与告别，最终回到当下。

采用“上方场景图、下方文字和选项”的布局，包含章节地图、剧情回顾、浏览器存档、背景音乐与音效。场景图目前为原创几何占位图。

- **在线游玩：** [求是西行 · 1937](https://2008ccy.github.io/qiushixixing/)
- **代码仓库：** [2008ccy/qiushixixing](https://github.com/2008ccy/qiushixixing)

## 本地运行

游戏使用 HTML、CSS 和原生 JavaScript，没有后端、数据库或构建步骤，不需要安装 Node.js、Ren’Py 或执行 `npm install`。

下载并解压整个仓库，在包含 `index.html` 的文件夹中打开终端。已安装 Python 3 的 macOS / Linux 电脑运行：

```sh
python3 -m http.server 8000
```

Windows 可运行：

```powershell
py -m http.server 8000
```

浏览器打开 [http://localhost:8000/](http://localhost:8000/)。停止预览时，在终端按 `Ctrl+C`。

也可以尝试双击 `index.html`，但浏览器对本地文件的存档和音频处理可能不同，建议通过本地 HTTP 预览。运行时保留 `assets/` 和 `qiushi_bgm/`，不要只复制 HTML 文件。

## 怎么玩

1. 点击“开始西行”进入故事；存在自动存档时可继续上次进度。
2. 普通对白**按任意有效按键或点击文字区继续**，不再显示单独的“继续”方框。输入框、弹窗、中文输入法组合输入及系统快捷键不用于推进剧情；选择题等互动需要操作对应控件。
3. 序章先查看箱子、合影和日记，再展开路线图。
4. 玩家姓名在第一章何九章自我介绍并询问“你呢？”之后确认。留空使用“江潮生”，最多十个字。
5. 根据页面提示完成选择、夜读问答、拼校训和校样等互动。长文本按句断行并分页，继续操作会先翻到下一页。
6. 通过工具栏查看手账、地图或存档。结尾回忆可播放或跳过，最后两问可以填写，也可以留白。

页面按视口分配图片和文字区域，适配电脑和手机。常用尺寸以无需整页上下滚动为目标；窗口特别矮时，文字区允许内部滚动，以保留完整内容和操作。

## 地图与章节回顾

路线依次为：

**校史馆 → 杭州·天目山 → 建德·梅城 → 吉安·泰和 → 广西·宜山 → 遵义·湄潭 → 杭州·归来**

- 每完成一章，自动回到地图；下一站以暖色呼吸光提示，点击进入下一章。
- 尚未解锁的地点不可进入。
- 点击已完成的地点，可以回顾本局实际读过的剧情、选择和回应。回顾不会改变分数、手账或当前进度，也不能借此重新选择。
- 中途打开地图后，可以返回原来的阅读位置继续。
- 最后一章完成后，先显示收尾地图，再进入回忆、结局与尾声。

地图是西迁路线示意，不是按比例绘制的地理地图。

## 存档与续玩

游戏使用当前浏览器的 `localStorage` 保存进度，无需注册账号。

| 功能 | 说明 |
| --- | --- |
| 自动存档 | 随剧情推进、选择和输入等操作更新，支持刷新或关闭后续玩。 |
| 手动存档 | 在存档面板保存当前进度，可保留另一处进度；再次保存会覆盖该槽位。 |
| 恢复内容 | 包含姓名、剧情位置、文字页码、选择反馈、未完成的互动、手账及地图进度等。 |
| 重新启程 | 重置本局、地图和手账，覆盖自动档；保留手动档。 |

存档只属于当前浏览器和网站地址，**不会跨设备或跨浏览器同步**。清理网站数据会删除存档；本地预览与 GitHub Pages 的存档也彼此独立。最终两问的输入随进度保存在本机，不上传服务器。

## 音乐与音效

已接入随剧情切换的背景音乐、校歌、环境声，以及按钮、翻页、相机、炮声等音效。

- 首次点击或有效按键后启用声音，不能依赖页面刚打开时自动播放。
- 默认总音量为 70%，可通过声音按钮静音，通过“音量”调整大小。
- 静音和音量设置独立保存在本机，重新开始游戏不会重置它们。
- 页面切到后台时暂停，返回后恢复。全部剧情和互动均可静音游玩。

素材目录包含备选文件，并非每个文件都已接入。当前校歌使用一份录音，真结局采用降速播放，没有单独录制的送别编曲或纯音乐版本。

## 剧情与结局

当前包含 **157 个剧情节点、5 种结局**。故事覆盖从校史馆穿越、杭州与天目山迁校、建德、吉安与泰和、宜山、遵义与湄潭，到 1946 年返杭并回到 2026 年的流程。

互动包括展品查看、关键选择、护书支线、三道夜读题、测量选择、拼校训、灯下校样、领取与点亮费巩灯、挂校牌等，并配有手账、走马灯和历史时间轴。补全内容包括小满加入队伍、周念东参军选择的回应、澄江学校与费巩送别等剧情。

<details>
<summary>结局规则（含剧透）</summary>

结局按以下顺序判定，先满足的条件生效：

1. 失误达到 3 次：**隐没·无名**。
2. 选择护书、书籍完整，且人心／薪火／求真三项分数的最大差不超过 2：**真结局·求是**。
3. 人心不低于另外两项：**藏书楼**。
4. 薪火不低于求真：**澄江**。
5. 其余情况：**湄潭灯**。

失误数不直接向玩家显示。回顾剧情或恢复存档不会重复结算奖励。

## 更新 GitHub Pages

当前项目使用独立仓库 `2008ccy/qiushixixing`，游戏地址为 [https://2008ccy.github.io/qiushixixing/](https://2008ccy.github.io/qiushixixing/)。

1. 将修改后的文件提交到该仓库。根目录应直接包含 `index.html`、`assets/`、`qiushi_bgm/` 和 `.nojekyll`，不要上传 ZIP 代替文件，也不要额外套一层目录。
2. 首次部署或检查设置时，在仓库 **Settings → Pages** 中使用 **Deploy from a branch → main → /(root)**。
3. 提交后查看仓库的 Actions / Pages 部署结果，等待发布成功再打开游戏验证。

仅保存本地文件不会更新线上页面。发布音频相关改动时，也要提交对应的音频素材。所有素材使用相对路径，可在 GitHub Pages 的仓库子路径下运行。

若页面仍是旧版，可尝试强制刷新；不要为了刷新页面而清除网站数据，以免丢失本机存档。

## 修改剧情与替换素材

在 `index.html` 中搜索以下脚本 ID：

| 区块 | 修改内容 |
| --- | --- |
| `story-data` | 剧情正文、选项、图片编号、效果、节点连接和结局文案。 |
| `game-core` | 初始状态、效果去重、姓名处理与结局规则。 |
| `qiushi-audio` | 音频文件映射、节点配乐、播放与音量控制。 |
| `game-engine` | 界面、互动、地图、回顾、存读档和键盘操作。 |

修改前建议用 Git 保存当前版本。改文案时尽量保留节点 ID 和连接；重命名节点还会影响地图、音频和已有存档。剧情 JSON 中的引号与逗号必须保持合法。

图片可以用同名 WebP 覆盖，例如 `assets/images/IMG-01.webp`，建议保持 **1600×900、16:9**。`IMG-25` 当前没有单独图片，主剧情和回顾都使用 `IMG-07` 替代。音频路径定义在 `qiushi-audio` 的 `files` 映射中，替换或重命名时同步修改路径。

占位图生成脚本不在当前仓库中，无需运行它即可使用或替换图片。正式素材的作者、来源和使用许可应另行登记，不能仅凭音频文件名认定已确认授权。

## 修改后的检查

当前没有构建命令或仓库内统一的自动化测试命令。修改游戏后，按涉及范围检查：

- 剧情连接、姓名确认顺序和分支是否正确，图片与音频是否能加载。
- 每章完成后能否回地图，回顾是否保持进度和分数不变。
- 刷新与手动读档能否恢复阅读页、选择反馈及未完成的互动。
- 键盘和点击推进、中文输入、长句分页、电脑及手机布局是否正常。
- 静音、快速推进、切换地图和切到后台是否出现音轨堆叠。
- 发布后重新检查线上版本，不把本地保存或旧测试记录当作部署成功。

更详细的规则和验证清单见 [AGENTS.md](AGENTS.md)。本文依据当前实现更新，不代表本次重新完成了全流程浏览器测试。

## 文本与历史素材说明

剧情依据仓库中的新版剧本，历史人物对白包含文学创作。护书段标注为 1939 年插叙，里程沿用剧本中的“2600 多公里”；这些整理不等于对全部史实的独立考证。

场景占位图不是历史照片、建筑复原或文物实物记录，未制作人物立绘和真实历史合影。图片详细用途见 [素材说明](assets/素材说明.md)。正式公开展示时，应继续核对史料引用及新增素材的使用许可。
